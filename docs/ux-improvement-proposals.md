# Durian Map 体験向上施策 提案書

作成日: 2026-09-13
対象: `frontend/src/app/page.tsx`, `frontend/src/app/components/MapView.tsx`, `backend/src/index.ts`（コミット `50c1086` 時点）

## 0. 現状の整理

Durian Map は「チェーン店を除いた独立系カフェを、地図とリストで探す」モバイルファーストのアプリ。
コードを読んだ上で、現時点の強みと、体験を損ねているポイントを整理した。

### できていること

- 現在地周辺検索（Nearby Search / 距離順）とエリア名検索（Text Search）の 2 系統
- チェーン店ブロックリスト（店名・ドメイン）による除外
- 地図とリストの双方向連動、選択マーカーの拡大アニメーション、クラスタリング
- 評価・口コミ数・営業中・写真の表示、保存（localStorage）、Web Share API によるシェア
- モバイルのボトムシート（half / full の 2 段階）、エラートースト、ローディングスケルトン
- 24 時間のサーバー側キャッシュ

## 1. 施策一覧（優先度順）

優先度は「ユーザー体験へのインパクト × 実装コストの低さ」で判定。
工数は目安（S: 半日以内、M: 1〜2 日、L: 3 日以上）。

### 優先度 A: すぐ効く・コストが低い

#### A-1. ファーストビューのオンボーディング（工数 S）

- 初回・未検索時に「現在地で探す」を主役にしたウェルカム状態を表示する
- 定番エリアのチップ（渋谷 / 鎌倉 / 京都 …）を並べ、ワンタップで検索開始できるようにする
- 「チェーン店は出ません」という価値提案を 1 行で伝える
- 効果指標: 初回訪問から初回検索までの到達率

#### A-2. カードに距離と「閉店まで」を表示（工数 S）

- 現在地検索時はカードに「350m」「徒歩 5 分」を表示する（Haversine で算出、API 追加不要）
- `regularOpeningHours.periods` を返すようにして「21:00 まで」「本日定休」を表示する
- 効果指標: カード → 詳細のタップ率

#### A-3. `alert()` を既存トーストに置換（工数 S）

- シェア URL コピー時の `alert('マップURLをコピーしました！')` を `setErrorMsg` と同じ仕組みの成功トーストに変える
- トーストを `error / success` の 2 種に拡張する

#### A-4. ボトムシート 3 段階化（工数 S）

- `collapsed`（ハンドルと件数だけ）/ `half` / `full` の 3 段階にする
- 地図のピンをタップしたら `collapsed` に落とし、地図上の選択カードを見やすくする
- 地図をドラッグしたら自動で `collapsed` に落とす

#### A-5. 地図スタイルの見直し（工数 S）

- 駅名・主要地名・鉄道路線のラベルを復活させる（駅からの位置関係はカフェ探しで最重要）
- 地図をクリーム基調のライトスタイルにして UI と世界観を揃える（南国トーンに統一）
- 現在地マーカーの青系を、デザイン案に合わせた色に寄せる

#### A-6. 「本命 / きになる」バッジの整理（工数 S）

- 意味が伝わらないので削除し、代わりに「保存済み」「近い」「高評価（4.5+）」のような情報バッジに置き換える

---

### 優先度 B: 検索体験の中核を強くする

#### B-1. 「このエリアで再検索」ボタン（工数 M）

- 地図を動かしたあと、地図上部に「このエリアで再検索」ボタンを浮かせる（Google マップ・食べログと同じ作法）
- バックエンドはすでに `lat / lng / radius` を受けられるので、地図中心と表示範囲から半径を算出して呼ぶだけ
- 効果指標: 1 セッションあたりの検索回数、離脱率

#### B-2. 半径・絞り込み・並び替え（工数 M）

- 半径: 500m / 1km / 1.5km / 3km のセグメント
- 絞り込み: 営業中のみ、評価 4.0 以上、口コミ 10 件以上
- 並び替え: 距離順 / 評価順 / 口コミ数順
- すべてフロントで完結できる（20 件を対象にクライアント側で処理）

#### B-3. 追加読み込み（工数 M）

- Text Search の `pageToken` を使い「もっと見る」で次の 20 件を取得する
- Nearby Search は `maxResultCount` 上限が 20 なので、半径を広げる導線で代替する

#### B-4. エリア入力のオートコンプリート強化（工数 M）

- 現状の `datalist` 12 都市を、Places Autocomplete（地域タイプ限定）に置き換える
- 入力途中に候補が出ることで「鎌倉」と「鎌倉市」のような揺れを吸収する

#### B-5. チェーン除外の可視化とオプトアウト（工数 S〜M）

- 結果件数の横に「チェーン店 7 件を非表示」を表示し、タップで一時的に表示できる
- 誤除外の報告リンク（GitHub Issue や Google フォーム）を置き、ブロックリスト保守のフィードバックループを作る

---

### 優先度 C: 「保存」を再訪の理由にする

#### C-1. 保存にメモ・タグを追加（工数 M）

- 「電源あり」「作業向き」「デート」など固定タグ＋自由メモ
- localStorage のスキーマを `{ cafe, tags, memo, savedAt }` に拡張する（既存データはマイグレーション）

#### C-2. 保存リストのシェア（工数 M）

- 保存済みカフェを URL クエリまたは短縮 ID にエンコードして共有リンクを作る
- 「鎌倉カフェ巡りリスト」のように友人と共有できるようにし、流入経路を作る

#### C-3. 保存カフェの地図表示と近い順ソート（工数 S）

- 保存タブでも現在地からの距離を表示し、「いま近い保存カフェ」を上に出す

#### C-4. 訪問済みチェック（工数 S）

- 保存カフェに「行った」フラグを付け、行きたい / 行った を切り替えられるようにする

---

### 優先度 D: 詳細情報の充実

#### D-1. 詳細パネルの情報追加（工数 M）

- 営業時間の全曜日表示、価格帯（`priceLevel`）、電話番号、Google レビュー抜粋 2〜3 件
- 写真を横スクロールで複数枚表示
- Place Details API の追加呼び出しは、詳細パネルを開いたときだけ行いコストを抑える

#### D-2. 写真 URL のプロキシ化（工数 S）

- `places.googleapis.com/.../media` へのアクセスをバックエンド経由にして、クライアントに API キーを出さない
- Maps JavaScript API 用キーと Places 用キーの分離方針（README 記載）とも整合する

#### D-3. 「ここに行く」導線の強化（工数 S）

- Google マップ検索リンクではなく `google.com/maps/dir/?api=1&destination=...` で経路案内を直接開く
- iOS では Apple マップも選べるようにする

---

### 優先度 E: 基盤・品質

#### E-1. PWA 化（工数 M）

- `manifest.json` とサービスワーカーでホーム画面追加を可能にする
- 保存カフェはオフラインでも閲覧できるようにする

#### E-2. アクセシビリティ（工数 S〜M）

- 黄色地に黄文字の評価バッジなど、コントラスト比 4.5:1 を満たさない箇所を修正
- タップ領域を最小 44px に揃える（ハートボタン・閉じるボタン）
- デスクトップで hover 時のみ現れるシェアボタンを常時表示に変更
- ボトムシートのハンドルにキーボード操作・`aria-expanded` を付与

#### E-3. バックエンドの堅牢化（工数 S）

- キャッシュを LRU（件数上限）に変更する
- Places API のエラー本文をログに出し、429 / 403 をフロントに区別して返す
- レートリミット（IP 単位）を追加する

#### E-4. 依存関係とドキュメント整理（工数 S）

- `leaflet` / `react-leaflet` / `@types/leaflet` を削除する
- `CLAUDE.md` を現在のカフェアプリ仕様に書き直す
- `ToDo.md` のチェック済み項目を整理し、本提案書へのリンクを張る

#### E-5. 最低限のテスト（工数 M）

- `isChainCafe` と距離計算、時刻判定に vitest でユニットテストを追加する
- ブロックリスト追加時の回帰を防ぐ

## 3. 計測したい指標

- 初回訪問 → 初回検索の到達率（A-1 の効果）
- 検索 1 回あたりの詳細表示数・外部リンククリック数（A-2, D の効果）
- 1 セッションあたりの検索回数（B-1, B-2 の効果）
- 保存率と 7 日以内の再訪率（C の効果）
- API コール数と Places API 費用（キャッシュ・Details 遅延読込の効果）

計測は Vercel Analytics か Plausible のような軽量なものから始め、イベント名は `search_nearby`, `search_area`, `open_detail`, `save`, `share` の 5 つに絞る。

## 4. デザイン案

南国風（トロピカル）のビジュアル案を Pencil で作成した。

- ファイル: `designs/durian-map-tropical.pen`
- 書き出し画像: `designs/durian-map-tropical.png`
- 画面構成: 検索トップ / カフェ詳細 / 保存一覧 の 3 画面（モバイル）

デザイン案の方向性:

- ドリアンの果皮の緑と果肉のクリームイエローを主色に、南国の葉や光の差し込みをあしらう
- 現行の緑・クリーム基調は維持しつつ、地図もライト系に統一して「一枚の南国の風景」として見せる
- カードは丸みを強め、距離・営業終了時刻・評価を 1 行で読めるようにする

確定したカラーコードは `docs/design-tokens.md` にまとめ、`globals.css` の CSS 変数に反映済み。Tailwind の任意値 `#xxxxxx` 直書きは順次この変数参照に置き換える。
