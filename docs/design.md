# Durian Map デザイン規約

最終更新: 2026-11-14

UI を実装・変更する人は、コードを書く前に必ずこのファイルを読むこと。
色の具体値は **`docs/design-tokens.md` が正**（このファイルでは重複させない）。
ビジュアルの元ネタは `designs/durian-map-tropical.pen`（プレビュー: `designs/durian-map-tropical.png`）。

## 0. 大原則

1. **フラット。グラデーションは使わない。**
2. **タグ（チップ）を飾りで置かない。**
   `.pen` のカード・詳細には `自家焙煎` `個人経営` `Wi-Fi` が描かれているが、
   これらは Places API から取れない。推測で出すことになるので**実装しない**。
3. デザイン案（.pen）は「雰囲気の参照元」であって、1px 単位のコピー元ではない。
   案に描かれていても、下の禁止事項に当たるものは**実装しない**。

## 1. 禁止事項（明示的に却下されたもの）

### グラデーション禁止

- 背景・ボタン・ヘッダー・カード、どれもグラデーションにしない。**単色（ベタ塗り）で塗る。**
- `linear-gradient` / `radial-gradient` / `conic-gradient` を新規に書かない。
- .pen 案の「現在地の周辺で探す」CTA はマンゴーのグラデーションになっているが、
  **実装では `--dm-cta`（`#F6A21B`）のベタ塗りにする。**
- `docs/design-tokens.md` に書かれている `（グラデ上端 #FBBF3F）` という注記は**無効**。使わない。
- **既存の負債**: `frontend/src/app/globals.css` の `body` に radial-gradient 4 枚 +
  linear-gradient が残っている。`body::before` のドットテクスチャも同様。
  これは**削除して `--dm-surface`（`#FFF7E6`）のベタ塗りに置き換える**。

> 例外は「写真の上に文字を載せるための可読性オーバーレイ」のみ。
> その場合も黒の不透明度（`rgba(0,0,0,.35)` 程度）に留め、色付きグラデーションにはしない。

### 不用意なタグボタン禁止

タグ（`自家焙煎` `レコード` `個人経営` `Wi-Fi` のような小さなピル）は、次を**すべて**満たすときだけ置く。

- [ ] 実データに裏付けがある（API から取れている、またはユーザーが付けた）。ダミー・推測で出さない。
- [ ] ユーザーの判断を助ける情報である（「そのカフェを選ぶ／選ばない」に効く）。
- [ ] 1 カードにつき **最大 2 個**。余ったら出さない（「+3」のような省略表示もしない）。

そして **タグはボタンに見せない**。

- 押せないタグ → 枠線なし・影なし・ホバー効果なし。ただの色付き文字。
- 押せるタグ（フィルタ等）→ 押せるとわかる見た目にし、**必ず実際にフィルタとして機能させる**。
  「見た目だけのフィルタ」は作らない。
- 状態バッジ（`営業中` `準備中` `行きたい` `訪問済み`）はタグではない。**状態バッジは押せない**ので
  上記の「押せないタグ」のスタイルに従う。

### その他やらないこと

- 意味のない装飾（斜めの帯、ノイズテクスチャ、背景の光彩、パララックス）。
- 1 画面に主要 CTA を 2 つ以上置く。**最重要 CTA は 1 画面 1 つ**（`--dm-cta` はそれ専用）。
- 絵文字をアイコンの代わりに使う。アイコンは SVG で統一する。

## 2. タイポグラフィ

| 用途 | フォント | ウェイト |
|---|---|---|
| ロゴ、アイコン内の文字、英字見出し、**数値**（評価・距離・件数） | **Co Headline**（Dalton Maag） | Light / Regular / Bold |
| 日本語（本文・見出し・UI ラベル全般） | **M PLUS Rounded 1c** | 400 / 500 / 700 / 800 |

ルール:

- Co Headline は**欧文専用**。日本語が混ざる文字列では M PLUS Rounded 1c にフォールバックさせる。
  `font-family: var(--font-display), var(--font-sans), sans-serif;` の順で指定する。
- 「4.8」「(212)」「280m」「12件」のような**数値は Co Headline**。ここが揃うとブランドらしく見える。
- ロゴ・マップマーカー・アイコン画像・デザイン案（Pencil / Figma）で文字を含める場合も
  **Co Headline Bold** を指定する。
- Geist は使わない。

**現状**: 下記はすべて導入済み（`frontend/src/app/layout.tsx` / `globals.css`）。

- [x] `frontend/src/app/fonts/CoHeadline-{Light,Regular,Bold}.woff2` を配置
- [x] `next/font/local` で読み込み、CSS 変数 `--font-display` として公開
- [x] `--font-geist-sans` → `--font-sans` にリネーム、`Geist_Mono` を削除
- [x] `globals.css` の `@theme inline` に `--font-display` を追加

### サイズと太さ

2026-11-14 に整理した（Unslop の監査。それまで 9 種類のサイズと、ほぼ全部が Bold だった）。
**階層は大きさと色で付ける。太さで付けない。**

| 役割 | サイズ | 太さ |
|---|---|---|
| 画面タイトル・詳細の店名 | 20px | Bold |
| カード内の店名、入力欄、主ボタン | 16px | Medium |
| 本文・ラベル・チップ | 14px | Regular / Medium |
| 補助テキスト（件数・住所・時刻） | 12px | Regular |

- 使うサイズはこの 5 段だけ。`text-[13px]` のような間の値を足さない。
- **Bold（700）は見出しと「その画面でいちばん大事な数値」（評価）だけ。** ボタン・ラベル・店名は Medium（500）。
- 文末の句点は、複数の文から成る段落にだけ付ける。見出し・ボタン・ラベル・コピーには付けない。

## 3. 色

**値は `docs/design-tokens.md` を参照。ここでは使い分けだけ定義する。**

- 面（パネル・シート・カード）: `--dm-surface`（紙の白 `#FFFDF8`）。**ベタ塗り**。
  色は地図・写真・営業時間の帯に任せ、面そのものには色を付けない（クリームは凹みと罫線に残す）。
- 主要アクション（地図でみる、送信、アクティブタブ）: `--dm-primary`（濃緑）+ 白文字。
- 最重要 CTA（現在地の周辺で探す）: `--dm-cta`（マンゴー）**ベタ塗り** + `--durian-seed-900` の文字。
  1 画面 1 つ。
- 保存・行きたい: `--dm-accent`（ハイビスカス）。**面積を小さく**。
- 営業中: `--dm-success`、背景は `--durian-lime-100`。
- 位置情報・補助: `--dm-info`。
- 罫線: `--dm-border`。1px。
- Tailwind は任意値（`bg-[#1F6B3F]`）を新規に書かない。`bg-primary` などトークン由来の
  ユーティリティか、`var(--dm-*)` を使う。

コントラスト: 本文は 4.5:1 以上を守る。クリーム地に黄色系の文字は**禁止**。
淡色地（`-100` 系）に文字を載せるときは `--dm-success-text` / `--dm-accent-text` を使う
（`-500` 系をそのまま文字にすると 4.5:1 を割る）。検証済みの比は `docs/design-tokens.md` 参照。

## 4. 形・余白

| 要素 | 角丸 |
|---|---|
| パネル、シート | 20px |
| カード、浮いた検索バー、トースト | 12〜16px |
| ボタン、入力欄、チップ、切り替え | 8〜10px |
| 状態バッジ、地図のピン、帯 | 999px（ピル） |

- **何でもピルにしない。** ピルは「状態を示す小さなもの」と地図のピンに限る。押せるチップやボタンは角丸 8〜10px。
- **入れ子の角丸は「外側の角丸 − 間の余白」**（4px 未満にはしない）。
  例: 角丸 16px のカードの中に余白 8px で置く写真は 8px。角丸 20px のパネルに余白 12px で置く写真も 8px。
- アイコンは 16px か 20px、線の太さ 1.5。これ以外の大きさを足さない。
- 余白は **4px グリッド**。よく使うのは 8 / 12 / 16 / 24。
- 画面の左右パディングは 16px。
- 影は 2 段階だけ。重ねない。これより強い影を作らない。
  - `--dm-shadow`（`0 2px 8px rgba(20, 83, 45, 0.08)`）: パネルの中のカードやボタン。
  - `--dm-shadow-float`（`0 10px 32px rgba(20, 83, 45, 0.18)`）: **地図の上に浮く面だけ**
    （検索バー・パネル・ボトムシート・「このエリアで再検索」・トースト）。
    地図は色と線が多く、1 段目の影では面の境目が読めないため 2026-11-14 に追加した。
- タップ領域は最低 **44×44px**（iOS HIG）。

## 4.5 画面の骨格

**地図を画面全体に敷き、UI はその上に浮かせる。**（2026-11-14 に全面改訂）

| | モバイル（768px 未満） | PC（768px 以上） |
|---|---|---|
| 検索バー | 上端に浮くカード。マーク + 入力欄 + 現在地ボタン | 左上のカード。ロックアップ + 入力欄 |
| 本体 | ボトムシート（角丸 24px）。3 段階 | 検索バーの下に続く左のパネル（幅 400〜432px） |
| 地図 | 全面 | 全面。視点はパネルの幅だけ右へ寄せる |

- **本体の中身は 1 か所に 1 つ。** 一覧と詳細は同じ場所で入れ替わる（詳細には「戻る」）。
  詳細を一覧の上に差し込んで一覧を押し下げない。
- **切り替えは本体の先頭の「さがす / 保存」**（タブのパターン。`ViewSwitch.tsx`）。
  下部タブバーは作らない。2 項目のために画面の下端を常に占めるのは割に合わない。
- **ボトムシートは 3 段階**: `peek`（切り替えの行だけ）/ `half`（画面の半分）/ `full`（検索バーの直下まで）。
  指に追従させ、離したときの速度と位置で止まる段を決める（`hooks/useSheetDrag.ts`）。
  動かすのは `transform`。`height` をアニメーションさせない。
- **未検索のときは初回表示（`Welcome.tsx`）を出す。** 最重要 CTA「近くからさがす」、最近の検索、定番エリア。
  **キャッチコピーや説明文は置かない**（2026-11-14 に却下。押せるものだけを並べる）。エリアのチップは押せば実際に検索する（§1）。
  最重要 CTA（マンゴー）は 1 画面 1 つ。検索後は検索バーの現在地ボタンがその役を引き継ぐ。
- **Google のロゴと帰属表示を隠さない。** パネルやシートに隠れる分は `--dm-inset-*` でずらす
  （`globals.css` の `.dm-map`）。地図に重ねる面を足すときは必ずここを確認する。
- 並び替え（近い順）は**現在地が取れているときだけ出す**。距離が出せないと意味を持たないため。
- 地図が読み込めないときも一覧と詳細は使える（`MapFallback.tsx`）。
- **ロゴは「最初の画面に戻る」ボタン。** 検索と選択を解いて初回表示へ戻す。
- **「AI に相談」（`AskAi.tsx`）は地図の左下**、Google のロゴの上に置く。押すと、いまの画面の内容
  （URL・候補の一覧・開いている店）を入れたプロンプトで ChatGPT / Claude を開く。会話はこのアプリでは持たない。
- 価格帯の絞り込みは 1 つだけ選べる（選んでいるものをもう一度押すと外れる）。

## 4.6 モーション

動きは「何が起きたか」を伝えるためだけに使う。飾りの動き（常時動くもの、パララックス、
スクロール連動の演出）は §1 のとおり作らない。

| トークン | 値 | 使う場面 |
|---|---|---|
| `--dm-duration-fast` | 140ms | 押下・ホバーの色、チップの切り替え |
| `--dm-duration-base` | 260ms | 一覧と詳細の入れ替え、トースト |
| `--dm-duration-slow` | 440ms | シートが段に止まる動き、一覧の出現 |
| `--dm-ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 既定。現れるもの・止まるもの |
| `--dm-ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位置が入れ替わるもの |

- 動かしてよいのは `transform` と `opacity` だけ。`height` / `top` / `width` を動かさない。
- 一覧の出現は 1 枚ずつ 28ms ずらす。ずらすのは先頭 8 枚まで（全部ずらすと待たされる）。
- **読み込み時の入場は 1 つだけ**（本体の中身が 1 回、短く上がる）。要素ごとに別々の入場を付けない。
- ホバーで大きさを変えない。ホバーは色か面の変化だけ、押下はごく小さな縮小だけ。
- **`prefers-reduced-motion: reduce` ではすべて止める**（`globals.css` の末尾で一括）。
  動きが無くても状態が分かるように作ること。

## 5. コンポーネント規約

### カード（カフェ 1 件）

左に写真（88×88、角丸 16px）、右に上から 店名（16px Bold、2 行まで）／ 評価・件数・距離 ／
営業状態 ／ 住所。**カード全体がタップ領域**。カード内に別のボタンを置かない（保存は詳細で行う）。
枠線と影は付けない。面の色（ホバーで `--color-surface-sunken`）だけで区切る。
2026-11-14 までは営業状態を 2px の枠線の色で表していたが、20 枚並ぶと枠の色が先に目に入り、
店名と写真が読みにくくなるためやめた。

出すのは次のもの。いずれも**値が取れたときだけ**出す。

| 項目 | 例 | 出典 |
|---|---|---|
| 評価・件数 | `★ 4.2 (993)` | `rating` / `userRatingCount` |
| 距離・徒歩分 | `350m 徒歩約4分` | 端末の座標との直線距離。徒歩は 80m/分 |
| 営業状態 | `● 営業中 21:00まで` / `● 営業時間外 8:00から` | `openNow` と `closesAt`（営業中）/ `opensAt`（閉店中） |
| 今日の営業時間の帯 | 6 時 → 24 時の細い帯。開いている時間を塗り、いまの時刻に線 | `weekdayDescriptions`（`TodayBar.tsx`）。詳細の営業時間と同じ絵 |
| 住所 | `東京都目黒区上目黒２丁目…` | `formatAddress()`。**営業時間が取れない店だけ**、帯の代わりに出す |

営業状態は「いつまで開いているか」まで出す。単なる `営業中` より行くかどうかの判断に効くため。
時刻はサーバーがレスポンス時に JST で計算した値を使う（24 時間キャッシュされた `openNow` は嘘をつく）。
文字は `--dm-success-text` / `--dm-accent-text`、先頭の点は `--dm-success` / `--dm-accent`。
数値は `.num`（Co Headline）。

保存済みのカフェは店名の右に `行きたい` / `訪問済み` の状態バッジを出す（§状態バッジ）。

### 詳細

一覧と同じ場所に入れ替わりで出る（§4.5）。上から順に次のものを置く。

1. 写真（モバイル 160px / PC 224px、角丸 20px）。左上に「一覧に戻る」。写真が無い店は面の色とマーク。
2. 店名（22px Bold）。
3. 評価と営業状態を 1 行で（箱で囲まない。数値は Co Headline 20px）。その下に種別・価格帯・距離を小さく。
   取れた項目だけ並べる。閉店まで 60 分を切ったら、時刻の代わりに「あと N 分で閉店」。
4. アクション。**主役は「ここへ行く」（Primary。Google マップの経路案内）**。保存と共有は Secondary。
6. 営業時間（`WeekHours.tsx`）。24 時間で 1 周する時計の文字盤に、開いている時間帯を輪で塗る。
   針は「いま」（今日の文字盤にだけ出す）。下の曜日を押すと、その曜日の文字盤に切り替わる。
7. 情報行（住所 / 電話 / ウェブサイト）。
8. 保存後だけ「行きたい / 訪問済み」の切り替え。**いちばん下に置く**（保存を押した瞬間に、上の要素を押し下げないため）。
   保存ボタンは幅を固定する（「保存」→「保存済み」で隣のボタンが動かないように）。

### 地図のピン

札の形（星 + 評価）で出すのは、評価の高い 5 店と、選択中・ポインタが載っている店だけ。
ほかは小さな丸いピンにして地図を静かに保つ（全部を札にすると重なって読めない）。色の正は `components/map/pinStyle.ts`。

| 状態 | 面 | 枠 |
|---|---|---|
| 通常 | `--durian-cream-50` | 営業状態の色（`design-tokens.md`「営業状態の表現」） |
| 一覧のカードにポインタが載っている | `--durian-lime-100` | 同上 |
| 選択中 | `--durian-green-800`（文字はクリーム）。1.2 倍 | 面と同色 |

保存済みの店は右上に `--tropic-hibiscus-500` の点を付ける。

### ボタン

- Primary: `--dm-primary` ベタ塗り / 白文字 / 角丸 12px / 高さ 48px。
- Secondary: `--dm-surface` 地 + `--dm-border` の 1px 枠 / `--dm-text` 文字。
- CTA: `--dm-cta` ベタ塗り。1 画面 1 つ。
- アイコン + ラベルの縦積みは、3 つ並ぶアクション行（地図でみる / 保存 / シェア）でのみ使う。

### 「このエリアで再検索」ピル（地図）

検索した位置から地図を **300m 以上**動かしたときだけ、地図上部中央に出す。
`--dm-surface` 地 + `--dm-border` の 1px 枠 + 規約の影 1 種類、タップ領域 44px のピル。

**Secondary のスタイルにすること。** マンゴー（`--dm-cta`）にしない。
最重要 CTA は 1 画面 1 つで、それは「近くからさがす」が持っている（§1）。

半径は表示範囲の短辺 ÷ 2 を `500 / 1000 / 1500 / 3000 / 5000` に丸めて使う
（API 側がこの 5 つしか受け付けない）。押したらピルは消す。

### 絞り込みチップ（検索結果）

`営業中` / `〜¥1,000` / `¥1,000〜2,000` / `¥2,000〜` の 4 つ。**4 つとも実際に絞り込む**
（`design.md` §1「押せるのに効かない UI は作らない」）。価格帯は Places の `priceLevel` を
3 段にまとめたもの。価格帯どうしは OR、営業中とは AND。

折り返すと 2 行になってリストの高さを食うので、**横スクロールの 1 行**にする。
0 件になったら専用の空状態（「条件に合うカフェがありません」）を出す。

### 保存した状態（行きたい / 訪問済み）

保存すると既定は「行きたい」。詳細の切り替えで「訪問済み」に変える。
**保存していないカフェに状態は無い**ので、切り替えは保存後だけ出す。
保存の一覧の上部には、絞り込みチップ（すべて / 行きたい / 訪問済み）と件数を置く。

### 詳細の情報行

36px の角丸アイコン枠（`--dm-surface-sunken` 地 / `--dm-primary` のアイコン）＋
11px のラベル ＋ 14px の値 ＋ 右シェブロン。行全体がリンク。
住所 / 電話 / ウェブサイトの順。**値が取れないフィールドは行ごと出さない。**
営業時間は情報行ではなく、曜日別の表で出す（§詳細）。

### 状態バッジ

`行きたい` = `--tropic-hibiscus-100` 地 / **`--dm-accent-text`** 文字。
営業状態はバッジにしない。点 + 文字で出す（`design-tokens.md`「営業状態の表現」）。
`訪問済み` = `--durian-lime-100` 地 / `--durian-green-700` 文字。
**枠線・影・ホバーなし。**

> 文字に `--dm-success`（`#2E8B57`）や `--dm-accent`（`#E2467C`）を使わないこと。
> 淡色地の上で 4.5:1 を満たさない（3.60 / 3.17）。`-500` 系は面・枠・アイコン専用。

### 空状態・エラー

- 検索 0 件、保存 0 件は必ず専用の表示を用意する（白紙にしない）。
- エラーは `--dm-error` のトーストで明示する。無言で失敗させない。

## 6. Web / iOS 共通の注意

- このデザイン規約は **Web と iOS（Capacitor）で共通**。プラットフォームごとに分岐させない。
  → 方針の詳細は `docs/platform-strategy.md`。
- セーフエリアを考慮する（`env(safe-area-inset-*)`）。特にヘッダーと下部タブバー・ボトムシート。
  `layout.tsx` に `viewportFit: 'cover'` を入れてあるので `env()` は実値が入る
  （Web では 0 になるだけなので、常に足しておいてよい）。
  実装例: ヘッダーは `h-[calc(5rem_+_env(safe-area-inset-top))] pt-[env(safe-area-inset-top)]`。
- **ピンチズームを塞がない。** 以前は `layout.tsx` に `maximumScale: 1` を入れていたが、
  これは WCAG 2.2 の 1.4.4（テキストの拡大）違反なので削除した。
  元の目的は「入力欄をタップしたときの iOS の自動ズーム防止」で、それは
  **入力欄のフォントを 16px 以上にする**ことですでに達成している（`text-base` を下回らせない）。
  新しく入力欄を足すときも 16px 未満にしないこと。
- キーボード操作の現在地を消さない。`focus:outline-none` は使わず、
  `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary` を当てる。
- ダークモードは**現時点で対応しない**。ライトのみ。中途半端に `dark:` を足さないこと。

## 7. 永続化とブラウザ API

実体が Web と iOS で変わるものは `frontend/src/lib/` を必ず通す。
**UI コンポーネントから直接呼ばないこと**（iOS で差し替えられなくなる）。

| やりたいこと | 使うもの | 直接呼んではいけないもの |
|---|---|---|
| 保存済みカフェの読み書き | `lib/storage.ts` | `localStorage` |
| 検索・写真 URL | `lib/api.ts` | `fetch` |
| 現在地 | `lib/geolocation.ts` | `navigator.geolocation` |
| 共有 | `lib/share.ts` | `navigator.share` / `clipboard` / `alert` |

→ `docs/platform-strategy.md`

## 8. 変更するとき

- 色を足したくなったら、まず `docs/design-tokens.md` にトークンとして定義してから使う。
  コンポーネント内に直接 HEX を書かない。
- この規約から外れたいときは、勝手に外れず、このファイルを更新してから実装する。
